# 桌宠显示位置与重复实例

部署桌宠时同时检查显示模式、配置实例数量和运行实例；多个聊天会话不等于多个桌宠。不要通过删除会话、清空资料或批量结束 Electron 来处理。

## 首次配置与复用

- 首次在 DSH 桌面版部署、用户只需要一只桌面悬浮宠物时，采用一只目标宠物、`display=desktop`，不要默认为 `both`。网页模式使用 `web`；明确需要两处显示才使用 `both`。已有明确的多宠物/双端偏好保留，不擅自合并或删除。
- `both` 会在 DSH 页面和桌面悬浮窗分别显示；两个窗口中看到宠物不是两套安装。解释这一区别，用户要求只显示一只时再改为所需的单一显示位置。
- 修改前备份用户配置，只修改目标宠物的显示字段，保留大小、位置、人设及其他宠物。宿主运行时优先用当前版本支持的单宠物显示接口；宿主完全退出后才离线修改配置。JSONC 应保留注释，不用简单 JSON 反序列化重写复杂配置。
- dsh-pet 0.3.8 的已核实接口：宿主动态端口下 `POST /dsh-pet-7340/pet-display`，请求 `{ "id": "<实际宠物ID>", "display": "desktop" }`。必须核对当前安装版本源码、响应 `ok` 和读回状态；HTTP 200 也可能携带失败结果。不固定宿主端口，不把示例 ID 当全体用户的 ID。

## 排除真重复启动

1. 读取有效聚合配置，检查宠物条目数量及各自 display；默认文件与用户文件分别检查不能代替有效配置。
2. 枚举 DSH 主宿主、独立版桌宠及每个 electron-helper 的主进程和父进程。GPU/renderer/utility 是正常子进程，不能按 electron.exe 总数判断出现了几只宠物；一个 helper 也可以显示多只配置宠物。
3. 检查目标 profile 的 bundle/补丁是否重复注册、是否同时启动 desktop/web 或独立版。只修复已证实的重复入口，不删除其他用户刻意使用的 profile。
4. 保存/热重载时等待旧 helper 退出再启动新实例，避免连续并发保存；不要另跑 standalone 或手动启动 helper 来“补显示”。上游 0.3.8 发布说明包含配置变化时短暂双实例的修复；不能据此保证任何双显示都是同一故障，也不盲目升级或改包源码。
5. 确需结束遗留 helper 时先核实入口路径、父进程归属和当前活跃实例，只处理已确认遗留的目标；中断宿主任务需先征求用户确认。禁止批量结束所有 Electron、Node 或 DSH。

## 验收

报告显示模式、目标宠物数量和 helper 主进程数量。若做了实际重启/切换会话测试，确认没有新增宠物/遗留实例；未执行就写待验证。进程/配置检查不能替代视觉验收；没有合适视觉工具时请用户确认，不自动使用未经同意的 computer-use。
