# 按需选择、只读预检与接续

## 对话入口

先用用户已经给出的目标，不把菜单变成必须填写的问卷。将“RVS/换声/转歌曲”按上下文解释为 RVC；若可能是“文字说话”，只问一句“你要文字说话，还是把现有歌曲换成肥鱼音色？”不要靠术语让用户猜。

范围不明确时可这样问（编号见 SKILL.md）：

> 这套技能可以分别补桌宠、QQ聊天、说话语音、RVC翻唱、网易云/自己的音频、成品库优先、B站、抖音。你只选想要的部分就行，已经装好的我会检查并复用。回复编号（可多选）或直接说目标；不确定也可以先只检查，不改动。

不要一口气追问所有账号、安装盘、模型、音色、歌曲、社交权限。只在推进所选功能时问无法从本机判断、且会影响决定的事项。工具不支持多选时用普通文字菜单，不假装单选按钮能多选。

## 只检查相关内容

1. 读工作区规则；从实际宿主进程、CLI、用户提供路径和配置位置定位 DSH/profile。多个实例不能猜哪个账号，无法确定时询问。路径未知不全盘漫扫；先在已知安装根和受支持数据目录中查。
2. 只读核对版本、插件注册/加载、环境路径、必要依赖、当前队列和磁盘。状态接口字段按需提取，绝不整包打印配置、Cookie、令牌或聊天记录。只检查模式不安装、不创建环境、不重启、不修改开关、不登录、不发 QQ、不产生收费任务。
3. 文件存在只能证明“可能已安装”；健康还需加载/版本/已有测试证据。轻量本机版本命令可检查，渲染、联网合成、账号登录和发消息属于单独验证；只检查时先说明未验证，不为凑齐结果偷偷运行。
4. 路径可用即默认沿用：推荐新安装统一根目录不意味着强制迁移已有 C 盘或其他盘部署。只做 RVC 时不顺便迁 QQ/TTS/宿主；不为统一版本重装可用的 GPU 环境。
5. 本次包含 QQ 时，即使 Aurabot 未安装或配置已删除，也先独立查找已有 SnowLuma；可用 `scripts/find-snowluma.ps1`，多个候选不猜，未找到只问必要路径。区分“重装插件、复用网关”与“网关也全新安装”，按[通用安装复用流程](snowluma-setup-and-reuse.md)处理，不因用户重装或录教程自动清空整套环境。

建议给用户一张短表：功能｜现状与证据｜本次动作｜还需用户做什么。没有证据记“未知/待验证”，不能当缺失重新装。说明要下载的大致内容/体积、CPU/GPU路线、联网数据流、预计是否需要重启；数字不确定就标估算。

## 语音/唱歌的方案选择

用户选择说话或翻唱时，按 [电脑配置与语音方案选择](hardware-and-voice.md) 的规则检查 CPU、内存、显卡/显存、空间、已有可用后端以及是否接受联网。输出“你这台电脑适合什么、原因、要装哪几项、不用装什么、预计下载多少、会不会很慢”，再执行选定路线。只读检查时仅给建议，不联网合成或安装。不要把大肥鱼专属本地 TTS、网易云客户端或 NVIDIA 显卡说成所有用户必需。

## 按依赖补齐，但不扩大目标

| 选择 | 相关前置与复用 | 不要顺带执行 |
|---|---|---|
| 桌宠 | DSH + dsh-pet | Aurabot、QQ、语音、翻唱 |
| QQ 聊天 | DSH + Aurabot + 已有合规 OneBot/网关 + 本人登录 | 另装桌宠、TTS、RVC、社交 |
| TTS | Aurabot 的语音适配器 + 所选TTS；仅本机试听不要求QQ在线 | RVC、分离模型、网易云、替换已有音色 |
| RVC 翻唱 | 先查已有引擎/FFmpeg/分离组件/获许可模型；补缺。试唱只选一种音源 | 全套TTS、大模型、强制网易云登录、重复下载现有模型 |
| 网易云/自有音频 | 两者择需；选择网易云就自动补齐接入、复用登录或弹二维码扫码；自有音频先验文件。实际换声再查RVC | 为登录网易云安装桌面播放器，或强制用户同时提供本地音频 |
| 成品优先 | Aurabot 扩展点 + 可用持久目录/索引 + 已有文件；QQ重发需要可用QQ链路 | 为发送现有成品重新安装RVC、联网取歌或启动渲染 |
| B站 / 抖音 | 仅对应模块与所需登录/浏览器/可选FFmpeg | 默认开另一平台或开启点赞/评论/私信/自动任务 |

“部署唱歌”包含说明歌曲来源和成品复用的好处，推荐一起完成；但若用户明确只要环境、只修一个失败环节或只装模型，按其范围做，不自动装整个唱歌链。发现缺前置就说明“做 X 还缺 Y”，在授权范围内补齐；若涉及额外许可、付费、停机、覆盖或明显扩大范围，先让用户选。用户拒绝不阻碍独立可完成的部分。

## 可重复执行与续做

- 按依赖安排执行而非照菜单顺序逐项等待：SnowLuma 未安装只阻塞 QQ 接入和 QQ 收发验收，不阻塞已选桌宠、本机 TTS、已有音源的 RVC/成品库等独立项目。遇人工步骤记录“待用户操作”并继续其余已授权项目，所有可执行项目完成后集中交接。不能把本机验证冒充 QQ 验收；独立项目自身仍受许可、联网、费用和用户选择限制。
- 修改前保存所选字段/文件的本机备份，配置用已核实的部分合并；不要用旧快照覆盖全部新设置。
- 已安装且通过当前健康检查的项跳过；半成品先读错误再小范围修复。不取消队列、不清缓存、不删歌曲、不换账号来“重置到干净状态”。
- 执行记录至少包括：本次所选项、实际路径/版本、已改内容、备份、证据、待办和下一步。用户要求可续做文件时放到该用户的部署目录，不放分享技能包；不要记录秘密。
- “继续”先读本机记录并重新检查：原端口、登录、路径、队列可能改变。不要重跑已成功的扫码、下载、合成和外发。
- 部分失败时保留已成功部分，报告卡在哪一项；重复同一错误两次后停止该动作，改为诊断或请用户选择，而非无限重试。

## 场景核对

- “QQ 和桌宠好了，只补 RVC”：不弹全套菜单；预检翻唱链，保留 QQ/TTS；缺模型再讲来源与许可，音源二选一。
- “已有 NVIDIA 翻唱能用，只加网易云”：只查网易云入口/登录/取歌；不运行 CPU 安装器。
- “已有几首成品，点歌别重做”：只查库、索引、匹配与发送；不启动分离器、不重装 RVC。
- “已经 TTS，想要翻唱”：解释二者不同，复用已有 FFmpeg 等，但不误称 TTS 模型就是 RVC 模型。
- “先看看还缺什么”：只读检查；给候选项与建议，等选择再执行。
- “完整安装”：仍按缺项规划；已有成功的阶段跳过，外发/社交互动不默认全开。
