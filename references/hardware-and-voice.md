# 电脑配置与说话、唱歌的方案选择

本文件用于方案判断，不是让所有人安装一遍的清单。先检查、复用健康组件，再推荐最小可用方案。不要只按显卡品牌下结论，也不要为了追求音质擅自下载大模型。

## 先把四件事说清

| 能力 | 大白话 | 需要什么、不需要什么 |
|---|---|---|
| 聊天语音（TTS） | 把回复文字读出来 | 选一个可用语音引擎；不需要RVC、网易云、人声分离模型 |
| 翻唱（RVC） | 把已有歌曲中的人声换成肥鱼声音 | 可处理的演唱音源、分离器、RVC音色和FFmpeg；不要求先把歌词交给TTS朗读 |
| 点歌来源 | 去哪里取得要唱的歌 | 网易云内置入口或用户自己的音频，按需二选一；不强制装网易云桌面播放器 |
| 成品库 | 做过的直接发，不再算一遍 | 持久文件和正确索引；重发已有成品不要求TTS、网易云或RVC引擎正在运行，但QQ发送链要正常 |

“在线说话 + 本地CPU唱歌”是可以组合的。说话改用Edge，不会把唱歌也改成Edge，不要求更换RVC音色。TTS停用/不可用不代表唱歌引擎损坏；但QQ、宿主、磁盘或内存等共享环节出问题仍可能同时影响两者。不能保证CPU渲染不会拖慢聊天。

## 只读检查，再给建议

检查系统/CPU、可用内存、显卡具体型号/驱动/显存、选定磁盘余量、现有引擎/模型及实际运行后端。Windows可用 `Get-CimInstance Win32_Processor`、`Win32_OperatingSystem`、`Win32_VideoController` 和目标卷信息；如已有 `nvidia-smi`，可查询NVIDIA显存/驱动。`Win32_VideoController.AdapterRAM` 对大显存可能截断，不能据此硬判只有4GB；未知就写未知。不要为了检测安装驱动或大环境。

仅有显卡型号、`cuda.is_available()`、组件ready标志都不足以证明整条链已加速。分别检查人声分离、音高提取/RVC的实际设备；有步骤回落CPU须说明。用户只要求方案/检查时不跑渲染；已选择部署时先短音频测试，并用真实耗时决定是否适合日常使用。

询问本机无法判断的偏好：是否接受文字发往在线语音服务、是否必须离线/固定角色音色、能否接受唱歌等几分钟以上。已明确过的不重复问。不要要求用户自己认识CUDA/ROCm等缩写。

## 首选建议表（不是官方最低配置承诺）

| 本机情况/需求 | 说话建议 | 唱歌建议与边界 |
|---|---|---|
| 已有本地或在线方案能用 | 沿用，先验收 | 沿用实际可用引擎，不为教程改CPU版 |
| 普通笔记本、无独显或希望省资源，接受联网 | 先建议Edge并试听；没有固定肥鱼音色承诺 | 按当前兼容范围尝试CPU短片段；不能保证实时，太慢时先发已有成品或评估用户已有远端服务 |
| Windows AMD/Intel显卡，接受联网 | Edge不需要本地GPU推理；要离线另评估 | 本技能已有CPU准备路线。AMD/Intel加速要查对应引擎/系统/驱动，完成适配和实测后再启用，不直接安装CUDA版 |
| 受所选引擎支持的NVIDIA显卡 | 想省资源仍可用Edge；要本地角色语音再选兼容引擎 | 优先核对可用CUDA路线，分离与换声各自验收；显存不足先短片段/调整批量或CPU，不默认重装驱动 |
| 必须离线或不允许聊天内容上传 | 不推荐Edge作自动后备。评估可离线运行且与插件兼容的引擎；未接通先保留文字 | 本地已有音频可处理；网易云取歌仍需网络。仅引擎本地不代表整个宿主/聊天模型都离线 |
| 机器很紧张、共享任务多、可用内存/磁盘不足 | 轻量在线说话或文字 | 不硬装大环境、不启动并行渲染；先复用成品，用户选择清理/换目录/远端方案后再继续 |

内存8GB及以下且余量紧张时，保守推荐轻量说话与成品播放，不把大型本地模型作为默认；16GB可评估单任务CPU短片段；32GB可提供更大余量，但都不是速度/兼容保证。这些是本技能的保守规划建议，不是某个项目的最低要求。显存同样随具体版本、精度、模型、音频长度和并行任务变化，不能写“有8GB就全部能跑”或“没有N卡就只能机械音”。

## 说话引擎如何选和退路

1. **Edge**：较轻的本机客户端，语音在微软在线服务生成，需联网并说明文字会发送到服务。不是把大TTS模型下载到本机，也不必安装/打开Edge浏览器。通过第三方客户端访问，不承诺商业API级稳定性、永久免费或所有地区可用。选当前可用声音并试听；有晓北不等于拥有肥鱼本人的声音。
2. **CosyVoice / GPT-SoVITS 等本地引擎**：用户确实要离线或角色音色才评估。先选版本、核对官方设备支持和依赖、模型体积、授权参考音频及Aurabot适配器，再估算下载和运行资源。存在CPU/其他后端方案的项目不能一律称为“N卡专用”；能运行也未必能满足聊天延迟。不能将这个技能声称为已经提供所有引擎的一键安装脚本。
3. **用户已有兼容远端TTS**：先确认接口、费用、文本上传和凭据存储；没有已验证适配器就标待接入，不能编造接口。新开付费服务或上传参考声音须先说明并由用户选择。
4. **失败处理**：本地跑不动/适配失败→说明原因→提供Edge、已有远端或文字选项→用户选择后只改TTS。用户要求离线、拒绝联网或服务不可用时不强行Edge。不能默默退到Windows朗读，再称“自然语音已完成”；若用户愿意接受系统声音，可单独选并试听。

失败说明例：“本地说话模型在这台电脑上暂时没跑通。可以先用联网的Edge读回复，文字会发给微软服务；唱歌仍用原来的换声环境。也可以先只发文字。你更想用哪种？”这不是许可规避或代替用户确认。

## 歌曲来源与输出约定

- 用户选择网易云点歌时，默认接入Aurabot兼容的网易云搜索/取歌能力，并在未登录时自动展示二维码请用户本人扫码；用户明确不登录时保留其选择，不强制装桌面客户端。某首只能试听/不可取音频，先如实告知，再选用户有权提供的文件或可用版本。第三方其他平台只有当前插件确有支持或完成并验证适配后才列为可用，不能承诺全网歌曲都能下。
- 用户已给文件就先验文件，不再要求网易云。QQ直接接收附件并自动转换若尚未实现，要说明；本机文件处理可由Agent完成。详见 [CPU与RVC](rvc-cpu.md) 的“两种歌曲入口”。
- 用户要求说唱/歌词段/从某句开始，先核对歌曲版本与歌词时间，避免选成近名歌曲或大段前奏；不同翻唱的时间轴不通用。歌词时间只是定位线索，需要试听或可用对齐证据确认，不假装已经听过。
- 现有成品包含所需片段时直接裁剪，不重新分离/RVC；按实际剩余时长说明，不悄悄补足成60秒。如果要延伸到现有成品之外，再解释需要处理新片段。保留原文件备份，新成品和对应人声一起裁剪，更新时长/起点/哈希、带伴奏与清唱的关联及索引，确保后续命中新版。
- 要清唱就只发独立换声人声，不夹带带伴奏版；默认不永久删除原成品。用户明确要改变今后的默认编配时再调整并验收；“这次只发清唱”不等于授权删除全库混音。

## 下载体积、耗时和验收

分别解释“小音色模型”和“大运行环境/通用预训练模型”。下载前根据选定版本清单估算网络下载、解压后体积、缓存/临时音频和剩余空间，不拿“模型几十MB”当全套大小，也不写固定8GB适用于所有版本。RVC参考里的10GB余量只是历史环境粗略检查线，不是充分条件；实际组件清单和磁盘证据优先。空间不足先暂停并给选项，不擅自清缓存或移盘。

CPU新部署先测10–20秒，记录实际耗时，告知是短片段。每阶段超时与总任务时间分开讲；别保证歌曲几秒完成。用户要60秒或整首时再按其范围配置，排队串行优先，保留现有任务。

验收分别写：说话实际用哪个引擎/本机能否试听、唱歌用什么后端/是否产出、选定音源是否可用、成品和清唱是否入库、QQ是否收到并能播放。不要因Edge工作就写RVC成功，也不能因RVC慢就说Edge不能用。

- [RVC官方设备说明](https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI/blob/main/docs/en/README.en.md)：部分Windows路线有DirectML；与本技能固定Applio/Aurabot集成不同，不可直接套用。
- [Applio上游](https://github.com/IAHispano/Applio)：核对实际集成版本和引擎要求；本技能CPU准备器的版本限制仍适用。
