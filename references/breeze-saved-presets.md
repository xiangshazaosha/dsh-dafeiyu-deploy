## 导入步骤

1. 检查实际 Breeze 根目录、模型健康和现有 `voices/custom-presets.json`。**不改当前讲话、RVC、回复方式及QQ配置**。只选用户要的 ID；用户明确要整包才导入十三款。
2. 运行只读检查：

   ```text
   node scripts/install-breeze-presets.mjs --root <实际Breeze绝对根目录> --voices jiaojiao,feiye,lanyangyang_style,taiwan_jutian
   # 追加五款也可按需指定，例如 --voices aojiao_daxiaojie,nan_daxuesheng
   # 用户明确要整包时才省略 --voices
   ```

3. 用途已核对且本次允许导入后，在同一命令增加 `--apply --non-commercial`。离线校验格式和SHA256，已有相同文件复用；已有不同文件/同ID不同定义/冲突名称则停止，不提供强制覆盖开关。已有列表先备份后合并；其他自定义声音不删。许可和来源复制到 `<root>/licenses/dafeiyu-breeze-presets/<清单摘要>/`。按包版本分目录保存，不覆盖旧包来源记录。
4. 安装支持自定义音色的 `assets/breeze-voice/` v1.4.0 适配器，按 [模块安装流程](breeze-tts2-cpp.md#可复用扩展与配置)只检查/审查/备份后替换。已在工作的兼容模块不用重装：本案例原有 v1.2.x 已可读取扩展列表，更新技能不应替换它。泛化版通过每次读取运行目录元数据避免重复部署或热重载时的子模块缓存问题；引擎代码升级使用带版本的导入路径。
5. 仅在需要时重载 `voice`，核对 `/ext/voice-controls/state` 的讲话列表和原三项选择。可见入口为 **Aurabot → 系统 → 音色切换 → 讲话音色**；有列表并不代表已切换。主人命令示例 `/音色 台湾女生·巨甜普通话`，只在用户要求切换时执行对应选择。
6. 本机对选中音色生成短语，检查非空、可解码及用户试听。新增预设使用固定参考音色和风格 `instructions`，`cfg_scale=4`；旧四款保持原来的 `cfg_scale=1`，避免为新增音色更改旧音色效果。QQ真实发送另按用户范围验证，不自动发测试消息。

脚本只操作所选 Breeze 的音色文件、合并列表及许可记录，不联网、不启动引擎、不下载模型、不读取或修改Aurabot账号配置。新文件先完整写入再无覆盖发布，元数据最后发布；并发锁或元数据变动时停止。失败保留现状和诊断，不盲目重复覆盖。回退仅恢复本次列表备份，并检查正在使用的ID，不覆盖整份配置；旧音色文件可保留，勿递归清空目录。

## 四款文字V2

这四款是文字直接设计后保存的成品，不使用视频参考、人声提取或外部录音。默认直接校验导入 `.breeze`，不是部署时再次随机设计；提示词、种子、参考文本也保留，供明确要求调整时使用。见[文字V2部署与数据格式](breeze-text-v2.md)。`normalizeOutput=true` 仅对四款V2生效；需在runtime JSON显式配置已核对的 `ffmpeg` 路径，实际每次回复均做双遍响度统一，约-16 LUFS、真峰值目标-1.5 dBTP；旧音色不变，失败保留文字兜底。
