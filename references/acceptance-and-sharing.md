# 验收、故障与分享

## 交付清单

仅对本次所选功能及必要依赖验收。其他功能标“未选择/保持不变”，不因为清单列了所有能力就自动部署。交付本次改动、复用项和剩余待办，不把局部完成写成全套完成。

| 链路 | 最低成功证据 |
|---|---|
| 插件 | 实际版本、加载日志、桌宠和Aurabot可见 |
| 桌宠显示 | 核对有效宠物数量、display、helper 主进程归属；区分双端显示与重复启动，不按 Electron 子进程数判断。视觉/重启验收未做则明确待验证 |
| 路径 | 实际配置、默认提示、物理目录分别核对 |
| QQ | 总开关/试运行读回核对；机器人身份核对+经允许进行真实主人发句子+收到实际回复。只有开关开启或试运行成功不能算全链路通过 |
| TTS | 实际所选引擎合成成功、没有静默降级；需要QQ时另验语音可播放，不强制必须Edge |
| 可见设置/回复方式 | 核对当前导航与真正加载的独立面板；讲话/RVC分别保存不串改；文字、语音、双发、自动及失败文字兜底分别捕获测试，不把调概率当强制模式 |
| RVC | 依赖检查、CPU/GPU实际后端、分离、音色换声、用户试听 |
| 网易云 | 登录状态、搜索、指定版本与可用音频分别验证；凭据不进入分享包 |
| 用户音频 | 文件导入、可解码、原文件保留；QQ附件入口如未实现明确未完成 |
| 翻唱 | 真实短歌分离/换声/混音+QQ发回，不用ready标志替代 |
| 歌曲库 | 成品及元数据持久保存；QQ精确点歌唯一命中、权限不变、重复复用不重算；实际收件人可播放 |
| 清唱/接续 | 清唱和带伴奏音频/索引分开；清唱只读取对应换声人声；上一首上下文可接续且模拟不污染；新歌清唱不能漏发混音 |
| B站/抖音 | 登录状态、一次只读结果、授权动作的独立验证 |

先用大白话给出结果与剩余动作，技术版本/路径作为可查明细；不要用日志代替解释。硬件建议说明是已实测还是待测试的估计，本地TTS、在线TTS、RVC、音源和QQ发送分别报告。

最后报告可用/未完成/待用户操作/失败、全部实际目录、版本、声音ID、费用和联网数据流、备份/停用方法。不要把“设置好了”当用户一定收到消息。

仍有待办时，直接报告已完成项、具体阻塞、需用户本人完成的最少操作及之后的检查方式；用户完成后在当前会话复查并继续。不生成接续提示词，不要求复制到新会话。

交接前先完成其余已选、已授权且可独立执行的项目；只因 QQ 网关需要人工安装就结束全套部署不合格。报告按“已实测 / 待用户操作 / 因依赖暂未验收”分开列出，不能把后两者写成全部完成。

## 可复用的故障定位

- QQ connected却不回复：核对dryRun、总开关、bot/owner、白名单、真实入站事件、私聊上报告警、DSH模型登录/额度/本轮错误，再看发送回执。按消息唯一标记和时间定位，不打印整段聊天。
- 没语音：确认组件目录和DSH进程环境、voice.enabled/engine、模型输出/语音意图、长度/心情概率、edge在线服务、QQ编码/发送结果。先本机`/voice/test`，不要直接克隆声音解决网络问题。
- 外部Python污染：子进程`-I`或局部清理PYTHONPATH，检查实际numpy/torch来源，不删系统Python。保存依赖快照和`pip check`结果。
- CPU慢：短片段、串行、记录耗时；不把CUDA包装进去就声称加速成功。不要用CPU短语成功推算整曲用时。
- 迁移：确认联接/新启动环境变量/旧默认；升级可能替换插件、源码补丁和链接，升级后重做状态/组件/短语验证。备份留本机，不自动删旧数据。
- 凭据/账号：不写共享包；不在失败日志中整包输出配置、HTTP Authorization或模型API Key。

## 给别人使用这份Skill

DSH官方skill发现说明：<https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/skills.md>。
目录结构是`dsh-dafeiyu-deploy/SKILL.md`，与`scripts`、`references`、`assets`同层。不要多套一层目录。

安装本技能的clone/解压/放置也由收到用户请求的Agent完成；不要要求用户手工解压或移动。用户把压缩包或可信仓库地址交给现有Agent即可。先检查包内路径、排除越界解压条目和多余嵌套层，已有同名技能先备份，不覆盖其他技能。

方式一：Agent放在某个工作区的`.dsh/skills/dsh-dafeiyu-deploy`，在该工作区与Agent对话。
方式二：Agent放`<实际DSH_HOME>/skills/dsh-dafeiyu-deploy`，通常是`~/.dsh/skills`，但用户自定义DSH_HOME时不能照抄。
当前DSH也发现`.agents/skills`等根；发现失败先看实际skill provider配置，不盲目重启/重装。

可调用`/dsh-dafeiyu-deploy`（依宿主版本），或直接说：“使用 dsh-dafeiyu-deploy。我已接通 QQ，只补 RVC 翻唱。先检查并复用已有环境，说明缺什么，只改这部分。”也可说“先只检查，让我选择需要的功能”。
用户尚未安装本技能时，可以直接把压缩包交给Agent并说：“请检查并解压这个技能包，安装到我的DSH技能目录，读取SKILL.md。先介绍可选功能，按我选的部分检查已有安装，只补缺项，不默认全装；普通操作由你完成，必要的许可确认、扫码和权限选择再提示我。”无需向用户讲解常规clone/解压命令。
如果宿主没有技能发现工具，可以把`SKILL.md`作为明确用户指令交给Agent，并让它按需读取相邻参考；这不是绕过软件许可。

压缩包只含本技能文档、辅助/测试脚本、独立歌曲库/Breeze/音色回复控制扩展源码、公开候选元数据，以及明确选定的**九款小型合成 `.breeze` 音色包及完整独立许可**。不含DSH、Aurabot、SnowLuma二进制、基础模型/RVC权重与索引、其他私人音色、参考/歌曲音频、私人歌曲清单、登录资料、QQ号、API密钥、runtime配置或用户配置。音色包不适用仓库CC0；上游其余组件分别按自身条款获取。别把整台机器的部署目录当skill共享。
