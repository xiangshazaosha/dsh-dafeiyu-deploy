# SnowLuma 首次安装、重装复用与加载故障

## 按实际环境区分安装起点

本流程面向所有使用者，不区分教学版与普通版。是否安装、复用或修复由本机检查结果和用户所选范围决定；录制教程只是重装场景之一，不改变功能、许可或执行权限。

- **只重装大肥鱼/Aurabot，保留独立网关**：先从配置、运行进程入口、用户目录和有限的常见目录定位 SnowLuma。即使 Aurabot 配置已被卸载，也不能据此宣布网关未安装。确认候选后接入，不重新下载、不迁移、不清配置或协议/凭据。说明“此处复用已安装网关”，不要冒充全新首次安装。
- **连 SnowLuma 也清空的首次安装**：先核对清理范围、备份和当前发行包许可。模型/用户资料保留与否分开确认。不存在的安装不能自动发现；无适用的脚本部署授权时仍由用户按许可手动取得和安装。不能保证只点一次协议就覆盖首次安装、QQ身份验证和异常处理。

用户提到稍后重装或录教程，不等于立即授权删除当前安装。先列范围，等明确开始。只在用户指定版本上操作，不自动升级为 latest 后复用旧版补丁。

## 安装前自动定位，不依赖旧插件配置

Windows 可运行随包只读助手：

```powershell
& '<SKILL_DIR>\scripts\find-snowluma.ps1'
# 用户给了安装根/准确目录时优先显式传入：
& '<SKILL_DIR>\scripts\find-snowluma.ps1' -Path '<已有SnowLuma目录>' -DshHome '<实际DSH_HOME>'
```

助手只查配置、进程与有限目录并核对包名/入口；不全盘递归、不登录、不注入、不改密码。只找到一个候选不等于已经健康，多个候选先核对当前使用者，不起第二份。零候选表示“在本次检查范围未找到”，不是全盘确定不存在；只问一次实际目录，不直接重装。

确认后在当前 Aurabot 已核实的部分保存接口中填写 `snowluma.dir`，读回核对。别把 `<ROOT>/SnowLuma` 默认提示当唯一位置。当前插件版本接口变动时先重新适配。

## 优先 AuraBot 管理，不默认把用户送去 processes 手工加载

接入步骤的优先顺序：核对安装及许可 → 本机控制台凭据状态 → 本人协议确认 → 机器人 QQ 登录/接入目标核对 → **Agent 打开 AuraBot 总开关并保持试运行** → Aurabot 账号定向接入、核对实际登录身份 → 完成支持的向导步骤 → 经用户允许进行真实收发验证。总开关开着和能真实回复是两个状态，不能遗漏前者，也不能跳过后者的授权与验收；详见[QQ 总开关部署步骤](qq-and-voice.md#总开关是-qq-部署步骤不留给用户猜)。

- 首次由 Aurabot 管理启动、且 SnowLuma 尚无控制台凭据文件时，**若当前插件与发行包确实支持** bootstrap，使用插件自身强密码生成和本机保存能力；不要先外部运行 launcher 创建临时密码，再默认让用户手工改密码。
- 如果 SnowLuma 已独立启动或已有凭据文件，而 Aurabot 没有保存对应密码，明确“已安装但尚未建立管理凭据”。不能假装可无密码接管、打印秘密、读浏览器密码库或静默删凭据。优先由用户在本机面板建立连接；官方支持的凭据管理/重置需核对版本、范围与用户确认，不反复重置。
- `/processes` 的手动 Load 是管理入口，不是每次安装都必须让用户操作的固定步骤。优先检查 Aurabot 的自动接入是否真正可用：总开关、向导、管理认证、autoAttach 和机器人账号匹配。首次 QQ 部署条件满足后由 Agent 实际打开总开关并读回验证，不能只报告“总开关没开”后结束；保留试运行，不为凑自动化擅自打开真实自动回复。已知加载崩溃先排障，不能机械执行开启。
- `hookAutoLoad=false` 不表示无法自动化：Aurabot 可通过已认证接口定向接入机器人。不要为省一次点击启用“加载所有 QQ”；始终避开日常个人主号。账号不明就暂停，不能拿主号试注入。
- 网页手动 Load 与 API 自动 Load 最终都要加载同一套原生组件。手动加载导致崩溃时，改成自动点击/自动调用不能修好组件，也不能把它包装成优化成功。

## QQ 加载后退出：停止复试，先查证据

出现一次与加载相关的 QQ 崩溃就暂停加载重试，不让看门狗对该故障循环注入；只在操作范围允许时停止相应重试，避免打断其他正常账号。不要重启主号来“再试一次”。

1. 按时间对齐 SnowLuma `Hook` 错误与 Windows Application 1000/1001 或 QQ 自身崩溃记录。`COMPONENT_LOAD_FAILED` 只能证明组件加载失败，不能单凭它断言是密码、协议、杀毒或某个具体版本不兼容。
2. 记录 SnowLuma、运行 Node、QQ 可执行文件版本、实际 QQ 版本目录/组件路径、架构与权限。QQ 启动器文件版本可能不同于实际加载的版本目录；不能只读 `QQ.exe` 一个数字就宣布兼容或不兼容。
3. 核对官方发行包完整性、支持矩阵和已知问题；权限应匹配，不默认提权、不关闭安全软件、不改专有二进制、不复制来源不明 DLL。日志只取必要脱敏错误，不共享原始账号数据。
4. 版本替换、QQ更新/回退或隔离测试须说明影响并由用户确认；只使用专用机器人账号。没有定位和成功证据前写“加载故障未修复”。正式使用前先验证一次完整链路；制作教程时同样先验证，再固定已验证版本。
