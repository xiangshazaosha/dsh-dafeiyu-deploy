# QQ 统一翻唱路由、原曲来源与成品复用

选中 QQ 翻唱、自动选歌、本地优先、音色串台、重复制作或成品复用开关时，和[翻唱部署](breeze-cover.md)一起读取。

## 必须区分三层

| 层 | 用途 | 控制 |
|---|---|---|
| 本地导入原曲 | 用户提供的待换声歌曲，不是已唱好的成品 | 默认优先；明确说“用网易云唱＋歌名”可跳过 |
| 分离缓存 | 已核验的人声、伴奏轨，仍可用新音色换声 | 原曲/片段/分离模型一致时复用，不受成品开关清空 |
| 已翻唱成品 | 已经使用某个引擎、音色和参数导出的最终音频 | 系统→音色切换→翻唱·统一设置→已翻唱成品 |

成品开关默认开启。开启只复用符合当前引擎/音色/版本及可核对参数的音频；切换音色后不能继续发另一种声音。关闭会重新换声而非重放旧最终文件，同时仍保留分离缓存；适用于试听新音色。也可单次说“重新翻唱＋歌名”绕过成品，不改全局设置。按钮立即保存，不开始制作/发送，不删除历史，只影响下一单。

Breeze 和关闭成品优先时的 RVC 都由统一制作路径处理；RVC 关闭时不能绕回原生 RVC 的最终混音缓存。开启时保留已选择的原生成品库支持，并按当前 RVC voice/pitch 过滤，缺少匹配元数据不冒充当前音色。新统一 RVC 成品也可从统一任务索引复用。

**关闭旧成品复用，不代表丢弃原曲来源索引。** 本地没有原曲时，可从已做成品的真实 `songId`、歌名和版本别名找回原曲身份，再按当前音色重新制作，不必重新猜歌手。`song-library.sourceHint` 只返回原曲ID及版本提示，不返回旧声音的MP3、已换声人声、voice或pitch；不能把旧RVC成品当未经处理的原曲再套一遍。取得音频仍须通过正常权限检查，不因索引存在绕过试听/版权限制；片段起点和时长按本次请求，不从旧成品备注猜歌词位点。

## QQ 调用路径及防串音

主人私聊的 `qq_song_cover` / `/sing` 必须进入同一个 `song.request` 对象。外层 `qq-router.mjs` 按保存的引擎或用户明确要求分流；`song-library` 的 request guard 放在其内层，通过共享 Symbol 协作，避免相互覆盖和叠加多层包装。检查 guardInstalled 与库 guard 状态，不能仅看模块“在跑”。

QQ 请求在开始搜索前锁定 engine、voice、arrangement、长度、Breeze 保留旋律或 RVC 变调、成品策略；新的 UI 默认和正在做的旧任务分开。已有制作/发送任务时不再并行开另一引擎；相同在途请求去重。完成后检查真实 engine/voice，再提交唯一指定版本。发送不确定不得自动重发或改用另一个引擎；“已提交”不等于“已收到”。

本机试听 `breeze_cover_create` 不自动外发。QQ 正在处理的同一单不能同时调用本机 create 或额外 send；模型提示词必须保留用户明确的引擎、重新制作及来源要求，不先搜索网易云而绕开本地匹配。

非主人/群聊不擅自重定向至主人，保留原权限边界；本套 Breeze QQ 适配限定主人私聊。原来有其它权限的系统先适配再安装，不为了演示放宽权限或开启外发。

### 当前已知显示边界（尚未合并）

RVC开启成品优先且未命中统一制作/原曲索引时，仍可能交给原生 `song.request` 制作；这条路径的 `current/queue/history` 不在统一制作页的 `jobs/qq.requests` 中。不能仅因统一列表为空就认定没有制作，也不能把等待队列为空误读为没有正在处理的任务。排查时分别只读核对 `/song/status` 和 `/ext/breeze-cover/state`，不要为了测试另点一遍或重启宿主。此显示合并未在本次实现，不宣称已修复；新部署保留这一边界。

## 本地原曲匹配

仅“本机导入”参与自动歌名匹配，匿名原曲缓存不按文件夹编号猜歌。未登记的下载目录不是曲库；登记后可自动扫描。不得把开发机目录当所有人的默认库或扫描整盘。

本地首先按完整登记歌名/别名匹配，不要求音频由原唱演唱；歌名与普通歌手提示分开时，即使提示是原作品歌手，也可使用唯一匹配的本地翻唱。已知歌手/原作品信用信息只帮助精确区分同名作品，不作为强制原唱证明。明确“某人版、原唱版、现场、伴奏”等才保留版本约束，不能抹掉；不拿短子串误命中其它歌曲或把同名多个真正版本随便混成一个。

### 自动入库目录

入口为“系统→翻唱制作→本地原曲库·自动入库”。登记用户选定的绝对路径后，每5秒扫描该目录第一层的新音频（需复制/写入完成）。支持暂停、立即扫描及停止监控；不自动唱歌、发QQ、删除源文件或清空成品。新部署默认没有监控路径，必须使用目标机器上用户选定的目录。只登记源码，不把开发机路径作为默认值。

内容哈希去重：已导入同一内容时只建立目录索引，不复制第二份、不覆盖手工登记歌名或原作信用信息。常见文件名 `01_歌名_演唱者.m4a` 自动去编号并分开歌名/演唱者，不自动推断原创歌手；复杂标题可在当前歌曲的“登记歌名→保存歌名”修正。两个确实不同的同名版本保留供选择，更新/停止监控不删原文件或历史。

`source-folders.json` 仅留本机，保存启用标志、用户目录及已读文件指纹。目录外链接/整盘根目录不自动遍历，单文件上限64MB、批次限制与稳定性检查防止读到正在写入的文件；大量文件分批处理。`POST /ext/breeze-cover/folders` 的 action 为 add/remove/enabled/scan；添加目录或扫描都不创建翻唱任务。QQ入口会先刷新指定目录，再找本地来源；RVC成品优先开启时仍先核对相符成品，没有成品也能用本地原曲制作，不绕到网搜。

`local-sources.json` 只在使用者本机产生，不随技能打包。复杂文件名须登记 canonical title；`artists` 是本地录音演唱者，`songArtists` 是原作品歌手匹配词，两者分开，不能把上传者/剪辑者误当原唱。登记依据使用者确认和真实来源元数据，不把开发机的个别歌曲关系自动写给所有人。

本机接口：`POST /ext/breeze-cover/local-source`，body 为 `{sourceId,title,artists,songArtists,aliases}`；只接受当前已导入 ID。导入文件名中的括号等符号会规范成下划线，按导入响应的实际ID/新条目识别，不用未规范的原文件名猜成功与否；保留原文件及规范前标题/必要别名。重复执行应先核对已有条目，避免重复导入造成同名选择题。

多条本地匹配先确认，不跳去网易云；明确指定本地但没有命中时报告缺失，不改搜网。`GET /ext/breeze-cover/source-preview?q=...` 只预览路由，不搜索/下载/排队/发送。验收必须包含用户实际说法、单/多歌手以及本地翻唱者与原作品歌手不同的情况。用户只给歌名时，模型不因工具建议带歌手而自行附加原唱限制，先按本地歌名处理。

## 网易云自动选版本

本地未命中或明确要求网易云时，原唱优先而非必须原唱：普通歌手词作为作品提示，优先其可用完整演唱录音；没有匹配原唱或完整音频不可用时，可按完整同名选择其它普通演唱来源，最终仍使用当前选中引擎/音色换声。只给歌名、没有指定演唱者时按平台相关性选择可用普通演唱录音，不为每个翻唱歌手出选择题；歌名同名账号不能被误判为指定歌手。排除钢琴、纯音乐、伴奏及 Type Beat；普通录音优先于现场、混音及短片段。替代录音的实际演唱者写入请求记录，不称作原唱本人或认证的官方母带。指定歌手仍匹配多个合作版本等真实歧义时确认，不凭歌名子串乱选。

搜索适配优先请求最多30个结果，不只使用原生短列表。自动选择前最多探测6个来源的完整音频权限，排除试听；服务异常报真实查询错误，不伪装成歌名不存在。明确要求原唱版、本人版、某人版、指定现场/混音时保留限制，不按默认替代放宽。同名作品/版本仍有多个**符合要求**而无法消歧的选项，才进入 needs_choice；没有符合明确限制或可用完整音频时标 source_unavailable，不拿无关来源凑选择题。正常重复条目不要求输入命令；确需确认可在制作页点候选或 `/coverpick 请求前缀 序号`。

版本可能写在搜索结果 alias，而不在 name：例如“某曲”的 alias 是某个DJ版，须一起校验及消耗请求中的版本词，不能因残留词误报无来源。原唱/翻自信用标注可帮助识别作品，不能将标注的原作歌手说成当前录音演唱者，也不放宽明确指定的版本。已做索引的同一原曲ID可跨成品音色/清唱版本合并为同一来源；不同ID且无法区分时才确认。普通原作品歌手提示也不应阻挡已确定歌名、版本的本地/索引来源。用户未指定RVC变调时不猜测男女换声要升12，省略参数沿用面板。

规则修复使旧候选失效时标 superseded，不自动开旧任务；新补本地索引后，旧网搜候选/未找到来源的记录不能继续挡住新的本地点歌。仅当主人明确要继续从未开始的旧单、当前引擎/音色/参数和身份仍一致时，`POST /ext/breeze-cover/qq/resume` 才可继续同一请求；已发送/发送不确定任务不可借此重发。导入的是短片段就按实际长度制作并说明，不循环凑默认时长、不冒充整曲。

QQ记录显示真实时间、状态，并将旧规则下的未找到来源/旧候选标为历史记录，不能让用户误以为更新后又失败。页面“按当前设置重试（制作后发QQ）”通过 `/qq/retry` 和当前 `profileRevision` 重新点歌；这是用户明确点击后才触发的生产请求，使用当前引擎/音色/默认变调，不悄悄沿用旧请求中的音色/升降调。仅允许当前主人重试未完成记录；已提交/发送不确定的任务不得借此重复发送，升级本身也不自动重跑。

## 索引和设置

- `ext.breeze-cover.reuseFinished`：唯一成品策略。由控制页 `POST /ext/voice-controls/select {kind:"reuse",enabled:true/false}` 保存，只改这项，不顺便应用未保存的音色草稿。
- `jobs.json`：统一任务索引，成品复用校验来源、引擎、具体音色、片段、歌词/参数和音色文件指纹，并核对两份输出位于正确任务目录。关闭后忽略已完成命中，但仍去重同一在途任务。
- `qq-requests.json`：QQ 请求及实际来源/引擎/音色/版本、状态与 jobId；不是账号配置。不要把它随共享包发布。
- 原生 RVC `大肥鱼歌曲库/歌曲库索引.json`：保留已有索引和文件，按真实制作记录补 voice/pitch/engine 等，不用改元数据来伪装声音。详见[成品库](song-library.md)。

制作页只传统一 `profileRevision` 与来源/片段参数，不允许旧页面再传独立 engine/voice/arrangement/reuseFinished。设置变化时旧请求先刷新确认；`POST /ext/breeze-cover/reuse-preview` 接收同样的只读参数，可检查开启/关闭是否命中已做成品，绝不代替 start。

## 验收和分享边界

离线运行 `scripts/test-cover-*.mjs`，检查真实工具对象（可选）、包装顺序、来源匹配、网易云版本排序、成品开/关、RVC 原缓存绕过、错误音色拦截、重复提交/不确定发送和独立保存。没有授权不要在真实宿主模拟“未命中”的点歌，可能真的开始制作。运行主人的真实生产点歌与测试发送分开记。

分享包只含源码、泛化测试、流程和十一款明确授权共享的合成预设；不含用户歌曲、导入目录、索引、别名关系、原始聊天/请求记录、Cookie/二维码、私人参考克隆或额外讲话轮换设置。把这轮能力写进技能，不等于把运行中的整个 data 目录打包。
